# P2 — Job store in a storage location the user chooses

**Goal.** Every job is a self-contained folder `<storage>/jobs/<id>/` with `job.json` as its record, plus a
rebuildable `index.json` for lists and search. The storage folder is chosen in `config.toml` or on System &
updates. Existing jobs are migrated. Plan: §5. Format: write the v1 job format into `docs/FORMATS.md` as part of
this phase.

**Before you start:** P0 done, including 0.5 (the owner copied the live `data/`) before this reaches the lab
server.

- [x] **2.3 `mister_plis/jobstore.py`: `JobStore`.**
  - Methods: `create(job)`, `save(job)` (atomic `job.json`), `get(id)`, `list(filters)`, `delete(ids)`,
    `rebuild_index()`, `import_folder(src, id)`.
  - It owns `<storage>/jobs/index.json`: one compact row per job; atomic writes; rebuilt when missing,
    unreadable or older than any `job.json`; a `modules` dict per row for flags later added by modules.
  - It has one lock.
  - *Check:* tests for rebuilding after deleting the index, for a corrupt `job.json` (skipped and reported, not

- [x] **2.4 `JobManager` on top of `JobStore`.**
  - `JobManager` keeps the thread pool, running jobs and cancellation.
  - History, lookups and cleanup go through `JobStore`.
  - Finished jobs are no longer all held in memory: `recent()` and `get()` read the index and the folders, with a
    small cache.
  - `Job.save_meta` writes `job.json`; it still writes `meta.json` for one release, so a rollback to `v1-final`
    still sees jobs.
  - *Check:* the existing `test_api.py`, `test_job_title.py` and `test_backup.py` are green unchanged.
- [x] **2.5 Input files kept with the job (D3).**

  - Record name, size, sha256 and path in `job.json → inputs`.
  - Above 200 MB in total, record name, size and sha256 only, with `"kept": false`.
  - A re-run from an old job uses `inputs/` when the upload has expired.
  - *Check:* a test where a job re-runs after its upload is gone.

  - *Check:* a test with a 600-row table, so that `tables/` holds all 600 rows.

## Done when

- the v0 fixtures load (`test_formats_v0.py` green);
- a fresh install creates `<storage>/jobs/`;
- an upgraded install shows all old jobs, their files download, and re-run works;
- deleting `index.json` and restarting gives the same job list;
- `FORMATS.md` documents job v1;
- the whole suite is green;
- tried on the Mac Studio through **Run another branch** with a copy of the real data.

## Rollback

Switch the server back to `release/v1`. Old jobs are still in `data/jobs.migrated-<date>`: rename it back.
Jobs created after the migration also have `meta.json`, so copying their folders into `data/jobs/` brings them
back.
