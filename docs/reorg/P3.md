# P3 — Backup v2 (human-readable) and re-import

**Goal.** A backed-up job is a folder anyone can read without MISTER PLIS (`README.md`, `results.xlsx`, plots,
files), and that MISTER PLIS can import back exactly (`mister-plis/` subfolder with a manifest). A shared
**backup catalogue** finds jobs in the backup folder, for Jobs & results and, later, Time Machine. Cleanup
deletes a job only after its backup is verified. Plan: §6. Write the v1 backup format into `docs/FORMATS.md`.

**Before you start:** P2 merged.

## Tasks

- [x] **3.1 The v1 backup format** in `docs/FORMATS.md`: the folder layout (plan §6.1), the `manifest.json`
  schema (§6.4), the README sections (§6.2), and the CSV rule (§6.3).
- [x] **3.2 Exporters: `mister_plis/export/`.** Each one is a pure function from a job folder and its `job.json`
  to files in a target folder.
  - `readme.py`: `README.md` **in English** (files on disk are always English), built from
    `report.describe_settings` and `describe_files` and the outputs:
    - metrics as a list;
    - Markdown and alerts as text;
    - tables as their first 20 rows plus a pointer to the sheet;
    - plots as images or links;
    - files as links;
    - the last 50 log lines.
  - `workbook.py`: `results.xlsx` with one sheet per table (from `tables/`, so the full table), a **Summary**
    sheet (job description and metrics) and a **Plot data** sheet (every trace's x/y, labelled). Use
    `excel.write_workbook`. Tables that can't fit go to `tables/<title>.csv` instead, never both.
  - `plots.py`: for each plot, `plots/NN_<title>.html` (plotly, `include_plotlyjs="directory"` with one
    `plots/plotly.min.js`), plus `.png` when `kaleido` imports (optional; add it to `requirements.txt` only as a
    comment and note it in the deploy doc).
  - `pdf.py`: `report.pdf` via `printout.results_pdf`, with the PNGs from `plots.py` as the charts when present.

  *Check:* golden tests on a fixture job. The README contains the person, the tool and each metric. The
  workbook has the expected sheets and the full row count. One `.html` per plot.
- [x] **3.3 The writer: `backup.py` v1.**
  - `copy_job` writes into `.partial/`:
    - the exporters' files;
    - the tool's own output files into `files/`, **skipping** outputs marked `"derived": "table"`;
    - `mister-plis/job.json`, `mister-plis/inputs/…` (if kept) and `mister-plis/manifest.json` (every file:
      backup path, job path or null, size, sha256), plus a short `mister-plis/README.txt`.
  - Then rename, then **verify** (re-read the manifest and check every checksum).
  - Only then set `job.json → backed_up = {at, folder, format_version: 1}`.
  - Update `<backup>/mister-plis-index.json`.
  - *Check:* the existing `test_backup.py` updated deliberately for the new files (say so in the commit), plus
    new tests for verification failing on a tampered file.
- [x] **3.4 The strict retention rule.** `JobManager.cleanup` / `Backups.pending` / `Backups.clear` delete a job
  only if no backup folder is set, **or** `backed_up` is set, the folder is reachable and its manifest
  verifies.
  - To keep it cheap, verify sizes on every cleanup, and checksums only once (`backed_up.verified_at`), plus
    when **Verify backups** is pressed.
  - *Check:* tests where the backup folder is unmounted, a file was changed, or the folder was deleted, and in
    each case the job is kept.
- [x] **3.5 `BackupCatalogue` in `backup.py`.**
  - `scan()` reads v1 folders (manifest) and v0 folders (`job-info.json`, or only the folder name).
  - `find(query)` moves `timemachine.normalize_query`/`matches` into the base, where Time Machine imports them
    from in the meantime.
  - The `<backup>/mister-plis-index.json` cache has a **Rescan** button.
  - `import_job(folder, into)`:
    - **v1:** follow the manifest and verify;
    - **v0:** files into `out/`, `job-info.json` → `job.json` via `jobformat.to_v1`, marked
      `"imported": {"from", "at", "format": 0}`.
  - *Check:* imports of `tests/fixtures/backup_v0` (both folders) and of a v1 folder written by 3.3. The v1
    round-trip gives identical `out/` checksums.
- [x] **3.6 Re-import in Jobs & results.**
  - Add `POST /api/jobs/import {folders}` and `GET /api/backup/catalogue?q=&person=&tool=`.
  - **Import from backup** on `jobs.html`/`jobs.js` searches the catalogue and imports the ticked jobs.
  - A job already in storage is skipped and shown.
  - Imported jobs count as backed up (to the folder they came from).
  - Add the Polish strings.
  - *Check:* API tests, and a manual check on the dev server.
- [x] **3.7 Time Machine switches to the catalogue,** still in its current place. `find`, `retrieve` and
  `_from_backup` call `BackupCatalogue`, so it reads v1 backups too. This is a small, safe step ahead of P4.
  - *Check:* `tests/test_timemachine.py` and `test_formats_v0.py` green.
- [x] **3.8 Upgrade old backups** (System & updates, a button, never automatic): rewrite a v0 folder into v1 in
  place (`.partial` + rename), keeping its files.
  - *Check:* a test on a copy of the v0 fixture.

## Done when

- a v1 backup is readable on a computer without MISTER PLIS (README renders on GitHub/VS Code, the workbook
  opens in Excel, the plots open in a browser offline);
- delete, then import, gives identical result files;
- v0 fixtures import;
- cleanup never deletes an unverified job;
- `FORMATS.md` documents backup v1;
- the whole suite is green;
- tried on the Mac Studio with the real NAS through **Run another branch**.

## Rollback

Switch to the previous release branch. v1 backup folders stay readable as plain files, and the old code ignores
the extra files. Nothing is deleted by P3, except what cleanup removes under the stricter rule.
