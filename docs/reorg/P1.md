# P1 — Tool SDK clean-up (tools stop reaching into the base)

**Goal.** Make `mister_plis.toolkit` the one and only API that tools use, with a version number. Tools can then
leave this repository in P7 without changes. Behaviour stays the same for the lab. Plan: §4.

**Before you start:** P0 done. You may run this in parallel with P2–P6. It only touches `tools/`, `toolkit.py`,
the locale loader, `pyproject.toml` and tests.

## Tasks

- [x] **1.1 Per-tool data folder.**
  - Add `toolkit.tool_data_dir(name: str) -> Path`, returning `<data_dir>/tool-data/<name>/` (created on demand).
    From P2 on it points into `<storage>/tool-data/…`; keep it behind this one function.
  - Point `tools/molarity.py` (`compounds.json`) and `tools/_assays.py` (`assays.json`) at it.
  - Add a one-time migration on first read: if the old `data/compounds.json` or `data/assays.json` exists and
    the new file doesn't, copy it over, and leave the old one in place.
  - *Check:* a test in which saved compounds and methods survive the move.
- [x] **1.2 `toolkit.find_program(name, setting=None)`.**
  - It wraps `settings.find_blender()`'s logic generally: a configured path, else known places, else `PATH`.
  - `blender_render.py` uses it.
  - *Check:* `test_tools.py` Blender skip logic unchanged.
- [x] **1.3 Re-export `trc` from the toolkit**, and make `tools/assay_reagents.py` import it from there.
- [x] **1.4 Relative imports for helpers.** `from tools._spectra import …` becomes `from ._spectra import …` in
  every tool file. The tests keep importing `tools.x` until P7.
- [x] **1.5 A guard test, `tests/test_tool_boundary.py`.** It parses every `tools/*.py` with `ast` and fails on
  any `import mister_plis.<x>` / `from mister_plis.<x>` where `x != "toolkit"`.
- [x] **1.6 `TOOLKIT_API = 1`** in `toolkit.py`. Then:
  - add an "API" section to `docs/ADDING_TOOLS.md`, listing every public name;
  - add `__all__` to `toolkit.py` with exactly that list, so the guard and the docs agree.
- [x] **1.7 The tools' translations live with the tools.**
  - Move `mister_plis/locale/pl_tools.py` to `tools/locale/pl.py`.
  - `mister_plis/locale/__init__.py` loads it from the tools folder. From P7 on, it loads one per tool source.
    Write the loader so it takes a list of extra catalogues.
  - The base's strings win on conflicts.
  - *Check:* `test_i18n.py` green. If it scans the locale folder by path, adjust it to the new loader, not by
    weakening it.
- [x] **1.8 The tools' tests live with the tools.**
  - Move `tests/test_tools.py`, and the tool-specific parts of `tests/test_report.py`, to `tools/tests/`.
  - Keep them collected by the root `pytest` run (`testpaths = ["tests", "tools/tests"]` in `pyproject.toml`).
  - Leave a base-only test of the toolkit in `tests/`.
- [x] **1.9 `pyproject.toml` for the base:**
  - name `mister-plis`;
  - packages `mister_plis` (and, after P4, `modules`);
  - runtime dependencies from `requirements.txt`;
  - pytest settings.

  Nothing changes for how the server starts.
  *Check:* `pip install -e .` in a fresh venv works, and `python -c "import mister_plis.toolkit"` succeeds.
